# Project Mayhem — data dictionary

Updated: 18 October 2026. Version: 0.1. Status: initial documentation baseline.

Paths in this document are relative to the project root unless a Markdown link is used.

## Provenance and limitations

The uploaded snapshots live under `src/ProjectMayhem/`, not a separate `data/` folder. They were inspected as CSV text without running broker-connected code. There are seven CSV files. All have headers and no symbol column. Do not infer instrument identity solely from their names.

`main.py` selects GBPJPY but writes `GBPUSD_15m_Data.csv` and `GBPUSD_1hr_Data.csv`. Prices near 199 are consistent with that code path, but the snapshots have no independently recorded symbol, broker, account currency or extraction provenance. Treat them as legacy fixtures of unverified instrument identity. No independently identified USDJPY series is supplied.

## OHLC schema

Applies to `Current_Candle_1m_Data.csv`, `GBPUSD_15m_Data.csv`, and `GBPUSD_1hr_Data.csv`.

| Column | Observed representation | Meaning / caution |
|---|---|---|
| `Date` | `YYYY-MM-DD HH:MM:SS`, no offset | MT5-derived bar time; timezone and completion metadata absent |
| `Open` | Decimal price | First quote represented by bar; bid/ask/mid basis unrecorded |
| `High` | Decimal price | Maximum represented bar price |
| `Low` | Decimal price | Minimum represented bar price |
| `Close` | Decimal price | Last observed bar value; not necessarily a final close |

`main.py` converts epoch seconds with UTC awareness, converts to `Europe/London`, then strips timezone information. That is observed writer behaviour, not proof that every supplied row was produced by that version. Preserve legacy timestamps as-is until provenance is reconciled; never silently relabel them UTC. DST boundaries can be ambiguous after offsets are removed.

The writer rounds OHLC prices to three decimal places for every symbol. It requests bars from position zero, so the latest stored bar may still be forming. Volume, spread, real volume and MT5 epoch are not retained in these CSVs.

## Derived zone schemas

| Dataset | Column | Observed meaning |
|---|---|---|
| FVG | `Date` | Middle candle's date, not the time the next candle confirms formation |
| FVG | `Prev_candle` | Bullish: previous High; bearish: previous Low |
| FVG | `Next_candle` | Bullish: next Low; bearish: next High |
| FVG | `Position` | `Bullish` or `Bearish` label |
| OB | `Date` | Candidate candle or merged preceding candle date |
| OB | `Open`, `High`, `Low`, `Close` | Candidate/merged zone values, not necessarily one raw bar |
| OB | `Position` | Code-assigned `Bullish` or `Bearish` label |
| Liquidity | `Date` | Candidate candle date |
| Liquidity | `Open` | Branch-dependent anchor: candle Open or Close |
| Liquidity | `Loc` | Price level at a High or Low; not an index or direction enum |

Normalise FVG display bounds using min/max, but retain the original fields. OB bounds and labels require reconciliation with the approved strategy. Liquidity output loses the `HrL` side and other branch context, so downstream code cannot reconstruct all semantics from the three columns alone.

Detector files are regenerated by the collector and later-row invalidation scans. They are current snapshot outputs, not an immutable event history and not proof that a historical entry was knowable. `Current_Candle_1m_Data.csv` is overwritten and contains one row; it cannot supply a trailing M1 confirmation sequence.

## Data-quality checks required before evaluation

Check numeric conversion, missing values, ascending timestamps, duplicate keys, expected session gaps, candle range consistency, completed-candle status, instrument identity, price basis, timezone and precision. Gaps outside trading sessions are different from missing active-session data. Build H1/M15 joins using information available at the event time.

All downstream execution and backtesting must use a documented spread/commission/slippage model. These files contain no fills, transaction costs, order IDs, trade outcomes or equity curve.
